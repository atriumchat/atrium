# Gomex Mobile

Expo SDK 58 / React Native 0.88, iOS 16+. Отдельное нативное приложение на основе `web/src/shell/MobileShell.tsx`: главная, сервер, профиль; разговоры открываются поверх вкладок с системным возвратом назад.

## Запуск

```sh
npm ci              # из корня репозитория: зависимости ставятся на все воркспейсы сразу
cd mobile
npm run ios
```

Для локальной iOS-сборки нужны Xcode, CocoaPods >= 1.15.2 и установленный iOS runtime либо подключённый iPhone. `npm run ios` создаёт development build. После установки этой сборки достаточно `npm start`. Обычный Expo Go не поддерживает используемый нативный LiveKit/WebRTC; нужен development build.

Для подключённого iPhone: `npm run ios:device`. На телефоне нужен режим разработчика; в Xcode — Apple Account и Apple Development-сертификат. iPhone и Mac должны видеть друг друга в локальной сети для загрузки JS из Metro.

Адрес действующего сервера вводится при входе. Можно заранее заполнить его через `EXPO_PUBLIC_SERVER_URL` в `.env.local` по образцу `.env.example`. Пароли, токены и секреты в переменные `EXPO_PUBLIC_*` не помещать. Для локальной разработки поддерживается `http://localhost:8010` в симуляторе; для устройства нужен HTTPS-адрес сервера.

Для сборки на телефоны через EAS предусмотрен профиль `preview` в `eas.json`; потребуются собственные Expo/Apple credentials и регистрация проекта. Профиль `development` рассчитан на симулятор.

## Реализовано

- «Свой сервер» со страницы входа, как в десктопе: IP и пароль VPS → SSH прямо с телефона (`modules/gomex-ssh`, Swift поверх Citadel 0.11.1 через Swift Package Manager) → бесплатный адрес на dedyn.io через deSEC или свой домен → установщик. Установщик запускается на сервере отвязанным от SSH (`setsid`, лог `/root/gomex-app-install.log`), приложение читает из лога шаги `::gomex` и показывает их барабаном. Свёрнутое приложение установку не прерывает, после возврата переподключается своим ключом из Keychain. В конце открывается веб-мастер сервера (`expo-web-browser`), потом вход с адресом нового сервера.
- Вход и регистрация по коду приглашения; показ ключа восстановления; сохранение API-токена в Keychain/Keystore.
- Главная с голосовыми комнатами, присутствием друзей и списком личных/групповых переписок; список каналов; профиль, статус, приглашения и переключение RU/EN.
- Друзья, приём заявок, открытие личной переписки.
- История каналов и лички, отправка сообщений, ответы, копирование, удаление своих сообщений, реакции, файлы и изображения.
- Голосовые и видеозвонки через LiveKit; микрофон, камера, системный выбор аудиовыхода iOS, отображение удалённого экрана. Фоновый audio mode включён в конфигурации.
- Системный таббар `NativeTabs` с иконками Gomex и аватаром: они рисуются как `<Svg>` вне экрана и передаются таббару PNG-картинками (`src/shell/TabIcons.tsx`). На iOS 26+ Liquid Glass рисует сама ОС; текущий звонок вынесен в нативный `BottomAccessory`. На более ранних iOS используется стандартный системный таббар, панель звонка — внутри экрана.

## Оптимизация

Виртуализированные `FlatList`, пагинация по 50 сообщений с парой `before` / `beforeId`, мемоизированные строки сообщений и аватары. До восьми переписок в памяти, до 500 сообщений в каждой неактивной переписке. В активной переписке можно загрузить всю историю; при уходе кэш сокращается. Один WebSocket, ограниченная частота read marks, повторная синхронизация после возврата/переподключения. Для изображений используется серверный preview и кэш в памяти; аудио и видео идут через нативный WebRTC, adaptive stream/dynacast включены.

Приватные медиа используют отдельную media-cookie, которую существующий сервер выдаёт на `/api/bootstrap`. Она передаётся только тому же origin и связана с текущим API-токеном. При выходе очищаются токен, данные и кэш изображений; штатный `/api/logout-all` отзывает сессии на всех устройствах, что явно указано в подтверждении.

Эти меры реализованы в коде. FPS, RAM, расход батареи и задержка звонков на реальном устройстве ещё не измерены.

## Проверки

```sh
npm run typecheck
npm test
npm run test:server
npm run export:ios
npx expo prebuild --platform ios --no-install
npx expo-doctor
```

`test:server` требует установленный `server/.venv` из основной инструкции проекта. Скрипт поднимает реальный бэкенд на свободном localhost-порту с отдельной временной БД, проверяет HTTP/WebSocket и удаляет тестовые данные. Он не подключается к действующему серверу. Проверяет вход, bootstrap, ACK и рассылку сообщений, курсор истории, реакции, read marks, личку, claims голосового токена, приватные файлы и отзыв сессии. Он не проверяет фактический медиапоток LiveKit.

На машине создания прошли TypeScript, тесты протокола, серверный контракт, Hermes-export iOS и нативная Debug-сборка под Xcode 27. Приложение подписано Apple Development-сертификатом и установлено на iPhone 17 Pro с iOS 27.0.1. Expo Doctor: 18/18. Установлены CocoaPods 1.17.0 и 116 pods. Внешний вид, клавиатура, разрешения и звонки на устройстве ещё требуют проверки. Первый запуск требует подтверждения доверия своему разработчику в настройках iPhone.

Локальный config plugin `plugins/withDeploymentTarget.js` исправляет сборку под Xcode 27: ресурсные targets зависимостей не могут иметь минимум ниже iOS 15.1, а Expo Router 55 использует API `subtitle` из iOS 16 без availability guard. Приложение и Expo Router поэтому собираются с минимумом iOS 16; настройка сохраняется при повторном prebuild.

## Границы этой версии

Push/CallKit и звонки при выгруженном приложении не интегрированы. Нет отправки собственного экрана, администрирования сервера/каналов, создания и редактирования групп, восстановления пароля и полной поддержки форматирования Markdown. Существующие группы доступны для переписки и звонков. Android сконфигурирован, но не собирался и не проверялся. NativeTabs в SDK 55 использует beta API; версии закреплены в lockfile.

Официальные руководства: [Expo NativeTabs](https://docs.expo.dev/router/advanced/native-tabs/), [LiveKit для Expo](https://docs.livekit.io/transport/sdk-platforms/expo/).
